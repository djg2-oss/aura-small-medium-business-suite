## Simulation & Memory Architecture (AuraXur OS)
- Nested simulations share **one** memory store (IndexedDB + localStorage fallback).
- Only one simulation "hot" (active); others are lightweight checkpoints.
- Growth of shared state reduces repeated computation → lower latency.
- On local computer: browser PWA preferred; host processes only as needed for heavy tasks. Elite status maintained via periodic cleanup (idle sims closed, log compacted, no full-disk scans).
- Result: sites and ops run organized, optimized, high-performance.
